Navigation that
writes itself.

NavEase is a Kotlin Multiplatform navigation library with four levels of integration: a single-line Gradle plugin that wires everything, @AutoRegister for zero-manual screen listing, a typed ActivityScreen<K> class API, and a zero-rebuild DSL. No reflection. No string routes.

Approach 1 — KSP Annotations 
// Approach 1 — KSP Annotations
@NavEaseScreen(route = "Main")
class MainScreen : NavScreen() {

    @NavEaseArgs
    data class Args(<val userId: String)

    @NavEaseResult
    data class Result(<val value: Int)

    @Composable
    override fun Content(navKey: NavKey, navController: NavController) {
        val args = navKey.mainArgs()   // ← KSP-generated ✅
        Text(<"Hello, ${args.userId}!")
        Button(onClick = { navController.backWithMainResult(value = 42) }) {
            Text(<"Return result")
        }
    }
}
// Approach 2 — navEaseGraph DSL (zero rebuild)
@Serializable sealed class AppScreen : NavKey {
    @Serializable data object Home : AppScreen()
    @Serializable data class  Detail(<val id: String) : AppScreen()
}

val graph = navEaseGraph(start = AppScreen.Home) {
    screen<AppScreen.Home>   { HomeScreen() }
    screen<AppScreen.Detail> { key -> DetailScreen(id = key.id) }
    //                          ^^^  typed — no casting ✅
}

// Navigate — no generated code, IDE resolves immediately:
nav.navigate(AppScreen.Detail(id = "abc"))
// Approach 3 — @AutoRegister + ActivityScreen<K>
@AutoRegister(startDestination = true)
class SplashScreen : ActivityScreen<AppScreens.Splash>() { /* … */ }

@AutoRegister
class DetailScreen : ActivityScreen<AppScreens.Detail>() {

    @Composable
    override fun Content(navKey: AppScreens.Detail, navController: NavController) {
        Text(navKey.id)   // ← typed, no cast, no xxxArgs() ✅
        Button(onClick = {
            navController.backWithResult(<Result(confirmed = true))
        }) { Text(<"Confirm") }
    }
}

// App.kt — KSP generates NavEaseHost() with all screens baked in
@Composable
fun App() {
    MaterialTheme { NavEaseHost(onExitRequest = {}) }   // ← zero config ✅
}

Features

Everything you need.
Nothing you don't.

NavEase gives you compile-time safety, zero runtime overhead, and a dead-simple API that doesn't get in your way.

⚡

Four Approaches

Plugin-only setup with zero boilerplate · @AutoRegister for automatic screen discovery · ActivityScreen<K> for typed class-based screens · navEaseGraph DSL for zero-rebuild. All share the same engine.

🔌

Plugin-Only Setup

One line: id("io.github.alims-repo.navease"). The Gradle plugin auto-applies KSP, adds navease-runtime, registers the source directory, and wires task ordering. Zero manual boilerplate.

🪄

@AutoRegister

Annotate any ActivityScreen<K> subclass with @AutoRegister. KSP generates autoRegisterScreens() and a complete NavEaseHost() overload — no manual add(XxxScreen()) ever needed.

🔄

Zero-Rebuild DSL

navEaseGraph { screen<K> { … } } — define screens in plain Kotlin. No annotation processing, no rebuild required after adding a screen.

🏗️

Typed ActivityScreen<K>

Extend ActivityScreen<K> and receive a fully-typed navKey: K in Content(). No casting, no xxxArgs() call — direct field access on your sealed key class.

🎯

Typed Arguments

@NavEaseArgs generates navKey.xxxArgs() extensions — no casting, no bundles, no string keys. Pure Kotlin.

↩️

Typed Results

@NavEaseResult generates backWithXxxResult() and xxxResult() extensions. Screen-to-screen communication with full type safety.

✨

Shared Element Transitions

Enable with one parameter: NavEaseHost(enableSharedTransitions = true). Use LocalNavEaseSharedTransitionScope in any screen, zero extra setup.

🔒

State Restoration

SavedStateConfiguration is generated and wired automatically. Your back stack survives process death out of the box.

🗺️

Powered by Navigation3

Built on JetBrains Navigation3 — the new Compose-first, serializable NavKey API. Works on every KMP target.

🔁

Smart Navigation

singleTop, popUpTo, popToIndex, replace (finish = true) — all the navigation patterns you need, typed and safe.

💉

Composition Local

LocalNavEaseController.current provides the nav controller to any deeply nested composable — no prop drilling.

Implementation

Path 1: Plugin + @AutoRegister

The fastest way to production. One plugin line, two annotations, and you're navigating.

1

Apply the Plugin

In your shared/build.gradle.kts:

shared/build.gradle.kts
plugins {
    kotlin(<"multiplatform")
    id("io.github.alims-repo.navease") version "<version>"
}

The plugin automatically applies KSP, adds navease-runtime, registers the generated source directory, and wires all compilation tasks to depend on KSP.

↓
2

Define Your NavKeys

Create a @Serializable sealed class in commonMain:

AppScreens.kt
@Serializable
sealed class AppScreens : NavKey {
    @Serializable
    data object Home : AppScreens()

    @Serializable
    data class Detail(<val id: String) : AppScreens()
}
↓
3

Annotate Screens

Extend ActivityScreen<K> and add @AutoRegister. Mark exactly one screen as startDestination = true.

HomeScreen.kt + DetailScreen.kt
@AutoRegister(startDestination = true)
class HomeScreen : ActivityScreen<AppScreens.Home>() {
    @Composable
    override fun Content(navKey: AppScreens.Home, navController: NavController) {
        Button(onClick = { navController.navigate(<AppScreens.Detail(id = "42")) }) {
            Text(<"Open Detail")
        }
    }
}

@AutoRegister
class DetailScreen : ActivityScreen<AppScreens.Detail>() {
    data class Result(<val confirmed: Boolean)

    @Composable
    override fun Content(navKey: AppScreens.Detail, navController: NavController) {
        Text(<"ID: ${navKey.id}")   // ← typed, no casting
        Button(onClick = {
            navController.backWithResult(<Result(confirmed = true))
        }) { Text(<"Done") }
    }
}

KSP validates at compile time: exactly one start destination, no duplicate NavKeys, and all screens must share the same sealed root.

↓
4

Host Your App

KSP generates a zero-config NavEaseHost(). Just drop it in your root composable:

App.kt
@Composable
fun App() {
    MaterialTheme {
        NavEaseHost(   // ← generated overload, zero arguments needed
            onExitRequest = { /* show exit dialog or finish() */ },
            enableSharedTransitions = true,
            navTransition = NavTransition.Push,
        )
    }
}
↓
5

Observe Results

In the parent screen, collect the typed result:

HomeScreen.kt (result observer)
val result by navController.resultOf<DetailScreen.Result>()
result?.<let { Text(<"Confirmed: ${it.confirmed}") }

Path 2: Plugin + KSP Annotations

Use @NavEaseScreen, @NavEaseArgs, and @NavEaseResult for full code generation.

1

Apply the Plugin

Same as Path 1 — one line in shared/build.gradle.kts:

shared/build.gradle.kts
plugins {
    kotlin(<"multiplatform")
    id("io.github.alims-repo.navease") version "<version>"
}
↓
2

Annotate Screens

Extend NavScreen and use the KSP annotations:

DetailScreen.kt
@NavEaseScreen(route = "Detail")
class DetailScreen : NavScreen() {

    @NavEaseArgs
    data class Args(<val id: String, val title: String)

    @NavEaseResult
    data class Result(<val success: Boolean)

    @Composable
    override fun Content(navKey: NavKey, navController: NavController) {
        val args = navKey.detailArgs()   // ← generated extension
        Text(args.title)

        Button(onClick = {
            navController.backWithDetailResult(success = true)   // ← generated
        }) { Text(<"Finish") }
    }
}
↓
3

Generated Host

KSP generates AppScreens, ScreenFactory, extensions, and a host. Use the generated NavEaseHost:

App.kt
@Composable
fun App() {
    MaterialTheme {
        NavEaseHost(   // ← generated, bakes in AppScreens.startDestination
            onExitRequest = {},
            navTransition = NavTransition.Push,
        )
    }
}
↓
4

Navigate & Observe

Use the generated extensions for type-safe navigation and results:

AnyScreen.kt
// Navigate with typed args
navController.navigateToDetail(id = "42", title = "Settings")

// Observe result
val result by navController.detailResult()
result?.<let { Text(<"Success: ${it.success}") }

Path 3: DSL Graph (Zero Rebuild)

No KSP. No annotations. Define everything in Kotlin and navigate immediately with full IDE support.

1

Apply the Plugin (Optional)

You only need the runtime. The plugin is optional for this path:

shared/build.gradle.kts
plugins {
    kotlin(<"multiplatform")
    // Optional: id("io.github.alims-repo.navease") version "<version>"
}

kotlin {
    sourceSets {
        commonMain {
            dependencies {
                implementation(<"io.github.alims-repo:navease-runtime:<version>")
            }
        }
    }
}
↓
2

Define NavKeys & Graph

Create a plain @Serializable sealed class and build the graph:

AppScreen.kt + Graph.kt
@Serializable
sealed class AppScreen : NavKey {
    @Serializable data object Home   : AppScreen()
    @Serializable data class  Detail(<val id: String) : AppScreen()
}

val appGraph = navEaseGraph(start = AppScreen.Home) {
    screen<AppScreen.Home>   { HomeScreen() }
    screen<AppScreen.Detail> { key -> DetailScreen(id = key.id) }
}

The screen<K> { } lambda receives the typed key — no casting required.

↓
3

Host the Graph

Pass the graph to the DSL overload of NavEaseHost:

App.kt
@Composable
fun App() {
    MaterialTheme {
        NavEaseHost(graph = appGraph)   // ← DSL overload
    }
}
↓
4

Navigate & Return Results

Use the runtime API directly. No generated code needed:

Navigation & Results
// Navigate
val nav = LocalNavEaseController.current
nav?.<navigate(<AppScreen.Detail(id = "abc"))

// Return result
data class DetailResult(<val ok: Boolean)
nav.backWithResult(<DetailResult(ok = true))

// Observe result
val result by nav.resultOf<DetailResult>()

Path 4: Manual Setup

Skip the plugin entirely. Full control, but requires manual wiring.

1

Apply KSP Manually

shared/build.gradle.kts
plugins {
    kotlin(<"multiplatform")
    id("com.google.devtools.ksp") version "<ksp-version>"
}

kotlin {
    sourceSets {
        commonMain {
            kotlin.srcDir(<"build/generated/ksp/metadata/commonMain/kotlin")
            dependencies {
                implementation(<"io.github.alims-repo:navease-runtime:<version>")
            }
        }
    }
}

dependencies {
    add(<"kspCommonMainMetadata", "io.github.alims-repo:navease-ksp:<version>")
}

tasks.withType<KotlinCompilationTask<*>>().<configureEach {
    if (name != "kspCommonMainKotlinMetadata") {
        dependsOn(<"kspCommonMainKotlinMetadata")
    }
}
↓
2

Forward KSP Args (Optional)

KSP Configuration
ksp {
    arg("navease.generatedPackage", "com.example.myapp.navigation")
}
↓
3

Use Any NavEase Approach

From here, follow Path 1 (use @AutoRegister) or Path 2 (use @NavEaseScreen). The runtime behavior is identical.

Configuration

Plugin Extension Reference

Every option available in the navease { } block.

Property Type Default Description
version String "" (plugin bundled) Pin a specific NavEase version for both runtime and KSP processor.
addRuntimeDependency Boolean true Automatically adds navease-runtime to commonMain. Set false to manage it yourself.
kspProcessorDependency Any? null (Maven Central) Override with project(":navease-ksp") for local monorepo development.
runtimeDependency Any? null (Maven Central) Override with project(":navease-runtime") for local monorepo development.
generatedPackage String "" Custom package for KSP-generated files. Forwards to navease.generatedPackage KSP arg.
Example: Local Monorepo Setup
navease {
    version = "0.0.3"
    kspProcessorDependency = project(<":navease-ksp")
    runtimeDependency      = project(<":navease-runtime")
    generatedPackage       = "com.example.myapp.navigation"
}

Transparent by design.

NavEase generates readable, auditable Kotlin. No magic — just code that you could have written yourself, but now you don't have to.

AutoRegisterScreens.kt — generated by KSP 
// Generated from @AutoRegister annotations
fun NavEaseScreenScope<AppScreens>.autoRegisterScreens() {
    add(<SplashScreen())
    add(<HomeScreen())
    add(<LibraryDetailScreen())
    add(<NavEaseDemoScreen())
    add(<SecureVaultDemoScreen())
    add(<FlowTabDemoScreen())
    add(<PrayerTimesDemoScreen())
    add(<CrashGuardDemoScreen())
    add(<PdfDemoScreen())
    add(<TransitionPreviewScreen())
}

// Generated NavEaseHost() — bakes in autoRegisterScreens() ✅
@Composable
fun NavEaseHost(
    onExitRequest: () -> Unit = {},
    enableSharedTransitions: Boolean = false,
    navTransition: NavTransition = NavTransition.Push,
) {
    NavEaseHost<AppScreens>(
        start = AppScreens.Splash,
        onExitRequest = onExitRequest,
        enableSharedTransitions = enableSharedTransitions,
        navTransition = navTransition,
    ) { autoRegisterScreens() }
}
NavEaseExtensions.kt — KSP annotations approach 
// Navigate with typed args — no casting needed
fun NavController.<navigateToMain(
    userId: String, age: Int,
    finish: Boolean = false
) = navigate(<AppScreens.Main(userId, age), finish)

// Access args — no Bundle, no casting
fun NavKey.<mainArgs(): MainScreen.Args {
    val key = this as AppScreens.Main
    return MainScreen.Args(key.userId, key.age)
}

// NavEaseResults.kt — typed result extensions

fun NavController.<backWithDetailResult(liked: Boolean) {
    backWithResult(<DetailResult(liked))
}

@Composable
fun NavController.<detailResult(): State<DetailResult?> =
    resultOf(<DetailResult::<class)
Module Structure

Clean separation.
Two artifacts.

📦

navease-runtime

KMP commonMain library

  • @AutoRegister — auto-discovery annotation for ActivityScreen subclasses
  • ActivityScreen<K> — typed abstract base; override Content(navKey: K, …)
  • @NavEaseScreen @NavEaseArgs @NavEaseResult — KSP annotation approach
  • NavScreen — non-generic base class (KSP approach)
  • NavController — navigate / back / popUpTo / singleTop / backWithResult
  • NavEaseNavGraph — core composable host engine
  • LocalNavEaseController + LocalNavEaseSharedTransitionScope
⚙️

navease-ksp

JVM KSP annotation processor

  • NavEaseProcessor — reads both @AutoRegister and @NavEaseScreen
  • Generates autoRegisterScreens() extension from @AutoRegister
  • Generates complete NavEaseHost() overload with start destination baked in
  • Validates: one NavKey → one screen · all screens same sealed root · exactly one startDestination = true
  • Also generates navigateToXxx(), xxxArgs(), backWithXxxResult() for @NavEaseScreen approach
🔌

navease-gradle-plugin

Gradle plugin · plugin ID io.github.alims-repo.navease

  • Auto-applies the KSP Gradle plugin — no id("com.google.devtools.ksp") needed
  • Adds navease-ksp to kspCommonMainMetadata automatically
  • Registers build/generated/ksp/metadata/commonMain/kotlin as a source dir
  • Wires all KMP compilations to depend on kspCommonMainKotlinMetadata
  • Optionally adds navease-runtime to commonMain
  • Forwards generatedPackage KSP arg · configurable via navease { } extension
  • Plugin version is auto-generated from gradle.properties at build time
