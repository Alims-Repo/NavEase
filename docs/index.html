KSP · Kotlin Multiplatform · Compose

Navigation that
writes itself.

NavEase is a KSP-powered, annotation-driven navigation library for Kotlin Multiplatform + Compose Multiplatform. Annotate your screen classes — KSP generates the route hierarchy, typed arguments, typed results, and the nav host at compile time. No manual registration. No reflection. No string routes.

Get Started → API Reference View on GitHub
MainScreen.kt 
@NavEaseScreen(route = "Main")
class MainScreen : NavScreen() {

    @NavEaseArgs
    data class Args(val userId: String, val age: Int)

    @NavEaseResult
    data class Result(val value: Int)

    @Composable
    override fun Content(navKey: NavKey, navController: NavController) {
        val args = navKey.mainArgs()   // ← KSP-generated, fully typed ✅
        Text("Hello, ${args.userId}!")
        Button(onClick = { navController.backWithMainResult(value = 42) }) {
            Text("Return result")
        }
    }
}

Features

Everything you need.
Nothing you don't.

NavEase gives you compile-time safety, zero runtime overhead, and a dead-simple API that doesn't get in your way.

⚡

Zero Boilerplate

KSP generates the entire route sealed class, screen factory, and all typed extensions at compile time. Annotate and go.

🎯

Typed Arguments

@NavEaseArgs generates navKey.xxxArgs() extensions — no casting, no bundles, no string keys. Pure Kotlin.

↩️

Typed Results

@NavEaseResult generates backWithXxxResult() and xxxResult() extensions. Screen-to-screen communication with full type safety.

✨

Shared Element Transitions

Enable with one parameter: NavEaseHost(enableSharedTransitions = true). Use LocalNavEaseSharedTransitionScope in any screen, zero extra setup.

🏗️

Class-Based Screens

Extend plain NavScreen — no generics, no generated types in your function signatures. IDE stays happy before the first build.

🔒

State Restoration

SavedStateConfiguration is generated and wired automatically. Your back stack survives process death out of the box.

🗺️

Powered by Navigation3

Built on JetBrains Navigation3 — the new Compose-first, serializable NavKey API. Works on every KMP target.

🔁

Smart Navigation

singleTop, popUpTo, popToIndex, replace (finish = true) — all the navigation patterns you need, typed and safe.

💉

Composition Local

LocalNavEaseController.current provides the nav controller to any deeply nested composable — no prop drilling.

Quick Start

From zero to navigating
in minutes.

The Gradle plugin wires everything automatically — KSP processor, runtime dependency, source directory, and task ordering. No boilerplate needed.

shared/build.gradle.kts 
plugins {
    kotlin("multiplatform")
    id("com.google.devtools.ksp")           // ← KSP (required)
    id("io.github.alims-repo.navease") version "<version>"  // ← NavEase plugin ✅
    // …compose plugins…
}

// That's it — navease-runtime, navease-ksp, srcDir, and task wiring are all handled.
Optional: navease { } extension 
// All optional — sensible defaults apply without any configuration.
navease {
    version = "<version>"            // pin a specific version (defaults to plugin version)
    addRuntimeDependency = true       // set false to manage navease-runtime yourself
    generatedPackage = "com.example.nav" // custom package for generated files
}

Prefer manual control? Add the dependencies and wiring yourself:

shared/build.gradle.kts 
// 1. Apply the KSP plugin
plugins {
    kotlin("multiplatform")
    id("com.google.devtools.ksp")
    // …compose plugins…
}

kotlin {
    sourceSets {
        commonMain {
            // Point KSP output so generated code is visible to all targets
            kotlin.srcDir("build/generated/ksp/metadata/commonMain/kotlin")
            dependencies {
                implementation("io.github.alims-repo:navease-runtime:<version>")
            }
        }
    }
}

dependencies {
    // KSP runs once — generates code for all platform targets
    add("kspCommonMainMetadata", "io.github.alims-repo:navease-ksp:<version>")
}

// Ensure all compilations depend on KSP output
tasks.withType<KotlinCompilationTask<*>>().configureEach {
    if (name != "kspCommonMainKotlinMetadata") {
        dependsOn("kspCommonMainKotlinMetadata")
    }
}

Annotate your screens — KSP handles the rest:

SplashScreen.kt + DetailScreen.kt 
// ─── Start destination (no args) ───────────────────────────────
@NavEaseScreen(route = "Splash", startDestination = true)
class SplashScreen : NavScreen() {

    @Composable
    override fun Content(navKey: NavKey, navController: NavController) {
        LaunchedEffect(Unit) {
            delay(800)
            navController.navigateToDetail(   // generated ✅
                featureName = "NavEase",
                description = "KSP-powered navigation"
            )
        }
    }
}

// ─── Screen with typed args & result ───────────────────────────
@NavEaseScreen(route = "Detail")
class DetailScreen : NavScreen() {

    @NavEaseArgs
    data class Args(val featureName: String, val description: String)

    @NavEaseResult
    data class Result(val liked: Boolean)

    @Composable
    override fun Content(navKey: NavKey, navController: NavController) {
        val args = navKey.detailArgs()   // generated, typed ✅
        Text(args.featureName)
        Button(onClick = {
            navController.backWithDetailResult(liked = true)   // typed result ✅
        }) { Text("👍 Liked") }
    }
}

Drop NavEaseHost into your composable root — that's the entire integration:

Android · iOS · Desktop 
// ─── commonMain / App.kt ───────────────────────────────────────
@Composable
fun App() {
    MaterialTheme {
        NavEaseHost()   // zero config required ✅
    }
}

// ─── Android ───────────────────────────────────────────────────
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent { App() }
    }
}

// ─── Desktop ───────────────────────────────────────────────────
fun main() = application {
    Window(onCloseRequest = ::exitApplication) { App() }
}

// ─── Receiving a result in the parent screen ────────────────────
val result by navController.detailResult()   // State<DetailResult?> ✅
result?.let { Text("Liked: ${it.liked}") }

Enable shared element transitions in one parameter — use them in any screen:

App.kt + ProfileScreen.kt 
// Enable once in your App composable ──────────────────────────
@Composable
fun App() {
    MaterialTheme {
        NavEaseHost(enableSharedTransitions = true)   // ← that's it ✅
    }
}

// Use sharedBounds in source screen (MainScreen) ──────────────
val sharedScope   = LocalNavEaseSharedTransitionScope.current
val animatedScope = LocalNavAnimatedContentScope.current

val avatarMod = if (sharedScope != null && animatedScope != null) {
    with(sharedScope) {
        Modifier.sharedBounds(
            sharedContentState = rememberSharedContentState(key = "avatar_alim"),
            animatedVisibilityScope = animatedScope,
        )
    }
} else Modifier     // ← zero overhead when disabled ✅

// Use the same key in destination screen (ProfileScreen) ──────
Modifier.sharedBounds(
    rememberSharedContentState(key = "avatar_alim"),   // ← keys must match
    animatedVisibilityScope = animatedScope,
)

Generated Code

Transparent by design.

NavEase generates readable, auditable Kotlin. No magic — just code that you could have written yourself, but now you don't have to.

AppScreens.kt — auto-generated 
@Stable @Serializable
sealed class AppScreens : NavKey {
    @Serializable data object Splash : AppScreens()
    @Serializable data class Main(
        val userId: String, val age: Int
    ) : AppScreens()
    @Serializable data class Detail(
        val featureName: String, val description: String
    ) : AppScreens()

    companion object {
        val startDestination: AppScreens get() = Splash
    }
}
NavEaseExtensions.kt — auto-generated 
// Navigate with typed args — no casting needed
fun NavController.navigateToMain(
    userId: String, age: Int,
    finish: Boolean = false
) = navigate(AppScreens.Main(userId, age), finish)

// Access args — no Bundle, no casting
fun NavKey.mainArgs(): MainScreen.Args {
    val key = this as AppScreens.Main
    return MainScreen.Args(key.userId, key.age)
}

// NavEaseResults.kt — typed result extensions
data class DetailResult(val liked: Boolean)

fun NavController.backWithDetailResult(liked: Boolean) {
    backWithResult(DetailResult(liked))
}

@Composable
fun NavController.detailResult(): State<DetailResult?> =
    resultOf(DetailResult::class)
Module Structure

Clean separation.
Two artifacts.

📦

navease-runtime

KMP commonMain library

  • @NavEaseScreen @NavEaseArgs @NavEaseResult annotations
  • NavScreen — abstract base class (non-generic)
  • NavController — navigate / back / popUpTo / singleTop
  • NavEaseNavGraph — core composable host
  • LocalNavEaseController — composition local
  • LocalNavEaseSharedTransitionScope — shared transition local
⚙️

navease-ksp

JVM KSP annotation processor

  • NavEaseProcessor — reads annotations, writes 5 files
  • Generates AppScreens sealed class per screen
  • Generates navigateToXxx() typed nav extensions
  • Generates xxxArgs() typed arg extensions
  • Generates backWithXxxResult() + xxxResult()
  • Generates NavEaseHost composable
🔌

navease-gradle-plugin

Gradle plugin · plugin ID io.github.alims-repo.navease

  • Adds navease-ksp to kspCommonMainMetadata automatically
  • Registers build/generated/ksp/metadata/commonMain/kotlin as a source dir
  • Wires all KMP compilations to depend on kspCommonMainKotlinMetadata
  • Optionally adds navease-runtime to commonMain
  • Forwards generatedPackage KSP arg when customised
  • Configurable via navease { } extension block
